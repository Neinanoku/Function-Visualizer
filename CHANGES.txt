FUNCTION VISUALIZER — ЧТО СДЕЛАНО В ЭТОЙ СЕССИИ
================================================

ФАЙЛЫ ДЛЯ СБОРКИ EXE (положить в одну папку рядом с .venv, ariadna-logo1-trnsp.png и icon.ico):
  app.py                  — окно программы (панель настроек слева, живой график справа)
  math_editor.py          — НОВЫЙ: 2-D редактор формул + экранная клавиатура-модель
  function_visualizer.py  — движок построения/анализа графика
  generate_spec.py        — генератор .spec (добавлен math_editor.py и папка fonts/, убран ttkbootstrap)
  fonts\                  — TeX Gyre Schola (4 файла .otf + лицензия) — шрифт программы
  build.bat               — сборка: pip-зависимости → spec → PyInstaller → dist\FuncVisualizer.exe
  app_he.py / generate_spec_he.py / build_he.bat — ивритская версия (см. раздел 7)
  tests\                  — 168 автотестов редактора, движка, bidi-раскладки и генератора спека (в exe не попадают;
                            запуск: python -m pytest tests -q)

1. ЖИВОЙ ГРАФИК (кнопки Plot больше нет)
  • График встроен в главное окно справа от панели настроек и перерисовывается сам
    через 250 мс после любого изменения (формула, цвет, толщина, окно, сетка, галочки, заливки).
  • Кнопка «Save image…» сохраняет картинку: PNG (200 dpi), SVG или PDF.
  • Колесо мыши над графиком — зум вокруг курсора, перетаскивание пустого места — панорамирование,
    «Reset view» — вернуть окно −5…5. Поля View Window при этом обновляются сами. Отдаление
    ограничено шагом сетки (не более 2000 линий): чтобы отдалить сильнее — увеличьте Step X/Y.
  • «Save project» / «Open project» — сохранение/загрузка всей сцены (формулы, стили, окно, сетка,
    галочки, заливки, свободные подписи, положение подписей осей и перетащенных подписей точек)
    в файл .fvproj (JSON).
  • Перетащенные подписи точек теперь ЗАПОМИНАЮТСЯ и не прыгают обратно при перерисовке
    (кнопка «Reset point labels» возвращает их на место). Свободные подписи и подписи осей
    переживают перерисовку, как и раньше.
  • Ошибки больше не выскакивают окнами: неполная/ошибочная формула подсвечивается красной рамкой
    (подсказка при наведении), остальные функции строятся. Неверные границы окна — сообщение
    в строке состояния, предыдущий график остаётся.
  • Тяжёлая символьная часть (sympy: пределы, особые точки, точные корни) считается в фоновом
    потоке и кэшируется: сначала мгновенно появляется график по численному анализу, через
    доли секунды подписи уточняются (статус «Refining labels…»). Повторные перерисовки той же
    функции — без задержек. Если sympy «задумался» дольше 20 с, сторож прекращает ожидание:
    такие подписи остаются десятичными (статус «Symbolic analysis timed out»), программа не виснет.
  • Непредвиденные ошибки построения не теряются: предыдущий график восстанавливается, а
    трассировка пишется в %LOCALAPPDATA%\FuncVisualizer\error.log (путь показан в строке состояния).

2. ПОЛЕ ФОРМУЛЫ БЕЗ КЛАВИАТУРЫ + ЭКРАННАЯ КЛАВИАТУРА
  • Поле формулы не принимает ввод с физической клавиатуры. Ввод только кнопками:
    цифры 0–9, точка, x, y, + − ×, =, a², aᵇ, √, ⁿ√, |a|, дробь (кнопки a/b и ÷ — обе
    создают двухэтажную дробь; строчного деления нет), скобки, π, e, eˣ,
    sin cos tan cot, ln, log (десятичный), logₐ (с основанием), а на странице «fn ▸» —
    arcsin arccos arctan sec csc sinh cosh tanh. Навигация: ← → ↑ ↓, ⌫, C (очистить).
  • Клавиатура общая, действует на активное поле (клик по полю делает его активным;
    новое поле становится активным автоматически). Если когда-нибудь понадобится ввод
    с физической клавиатуры — константа KEYBOARD_INPUT = True в начале math_editor.py.
  • Остальные числовые поля (окно, сетка, domain, заливка) — обычные, с клавиатуры,
    понимают pi, 2pi, pi/2, e, sqrt(2), inf.

3. ПРОФЕССИОНАЛЬНЫЙ ВИД ФОРМУЛЫ (как в Desmos, но компактно)
  • Степени — настоящие верхние индексы, дроби — настоящие двухэтажные, корень с чертой,
    модуль со скобками-палками, скобки растут под содержимое, пустые места (например,
    незаполненный показатель) показываются пунктирным квадратиком, курсор мигает.
  • Дробь «забирает» в числитель то, что стояло перед курсором (x² → «/» → x²/□), как в Desmos.
  • Внутри формула хранится как дерево и переводится в строку для движка автоматически
    (с явным умножением: 2x → 2*x, x(x+1) → x*(x+1)), так что ошибок разбора «2x» больше нет.

4. ДВИЖОК: ТОЧНЫЕ ПОДПИСИ ВМЕСТО «ОКРУГЛЯТОРА» ПО π/e
  • Старая схема (round до 4 знаков + «прилипание» к целому/π/e с допуском 2 %) убрана из пути
    подписей. Теперь:
    – корни, экстремумы, пересечения считаются численно с точностью ~1e-10 (brentq xtol=1e-12,
      экстремумы уточняются minimize_scalar), а НЕ по сетке;
    – параллельно sympy ищет ТОЧНЫЕ решения (solveset f=0, f'=0, f1=f2, пределы для «дырок»),
      и численная точка подписывается точной формой, если совпадает с ней: π/4, √2/2, 2π/3, e, 1+ln(5)…
    – если точного решения sympy не нашёл, используется строгая идентификация (nsimplify с допуском
      1e-9), которая принимается ТОЛЬКО если кандидат действительно корень/критическая точка
      (проверка подстановкой) и выглядит просто (малые целые, знаменатели ≤ 24);
    – иначе печатаются десятичные, как раньше (2 знака).
    Итог: «8 вместо 5π/2» и «прилипание к 5π/6» невозможны по построению.
  • Добавлен корень n-й степени nroot(x, n) (для нечётных n — вещественный корень из отрицательных),
    cbrt; логарифм по основанию log(x, b).
  • Вырожденные уравнения (y = y, x = x + 1) и участки, где функция тождественно равна нулю или две
    кривые совпадают, больше не порождают сотни подписей — такие строки получают понятное сообщение.
  • make_y_array векторизован (одно обращение к numpy вместо 6000 вызовов) — перерисовка быстрее.
  • Шрифт графика: Calibri с запасными вариантами (Carlito, DejaVu Sans) — без предупреждений.
  • Обработчики мыши предыдущего графика отключаются перед новым построением (нет утечек/дублей).
  • Standalone-запуск `python function_visualizer.py` по-прежнему работает (отдельное окно).

5. ПРОЧЕЕ
  • Убрана зависимость ttkbootstrap (не использовалась) — exe меньше, старт быстрее.
  • Логотип в шапке уменьшен, чтобы панель настроек занимала меньше места по высоте.
  • Галочки «Display on Graph» выстроены сеткой 3×3.
  • generate_spec.py не падает, если рядом нет логотипа/иконки (собирает без них).

6. ВТОРАЯ ИТЕРАЦИЯ (по замечаниям после первой сборки)
  • Плавность. Панорамирование и зум теперь мгновенные: пока строится новый кадр, поверх холста
    показывается последний кадр, сдвинутый/масштабированный вокруг курсора (как в Desmos), и он
    исчезает только когда новый готов — никаких пропадающих осей и пустого экрана. Сама
    перерисовка ускорена в 2–3 раза (без tight_layout, векторный поиск нулей и пересечений,
    кэш ключей sympy): типичная сцена из 2 функций — ~60 мс расчёта, 6 функций — ~200 мс.
  • Подписи на графике — через mathtext matplotlib: √5 с настоящей чертой, двухэтажные дроби
    (π/4, √2/2), (√21−1)/2, log₂(3) как log с индексом. Десятичные подписи и деления рисуются
    обычным текстом тем же serif-шрифтом (с настоящим минусом) — они не замедляют отрисовку.
  • Шрифт — TeX Gyre Schola везде (свободный клон Century Schoolbook с нормальной греческой π):
    на графике (подписи, деления, оси; математика mathtext тем же шрифтом, недостающие символы —
    из STIX), в панели настроек, на клавиатуре, в подсказках и в редакторе формул. Файлы шрифта
    лежат в папке fonts/ (лицензия GUST — свободное распространение) и попадают внутрь exe;
    устанавливать шрифт в систему не нужно: при старте он регистрируется для matplotlib и
    (на Windows) как приватный шрифт процесса для Tk. Если файлов нет — запасные шрифты
    (Century Schoolbook → Times New Roman → serif). Выбора шрифта в интерфейсе нет.
  • Подсказки клавиатуры (при наведении) переведены на английский — интерфейс полностью английский.
  • (Системный Century Schoolbook отвергнут: в нём греческая π неотличима от кириллической «п».)
  • Чёткий текст при масштабе монитора 125–200 % (Windows): программа объявляет себя DPI-aware,
    поэтому Windows больше не растягивает окно как картинку. Все пиксельные размеры (панель,
    клавиатура, редактор формул, окно) масштабируются по DPI, график тоже. Переменная окружения
    FV_UI_SCALE=1.5 задаёт коэффициент вручную (если понадобится крупнее/мельче).
  • Кнопки клавиатуры получили явную рамку в 1 px (Tk на Windows не рисовал её у белых кнопок).
  • Область построения всегда занимает всю отведённую площадь, а View Window задаёт масштаб
    по МЕНЬШЕЙ стороне холста: при равных диапазонах X и Y сетка квадратная, при разных —
    график растянут, как задано. Лишнее место по большей стороне не растягивает оси, а
    показывает дополнительный диапазон (при увеличении окна оси «удлиняются»); фактически
    видимый диапазон печатается в строке состояния («visible x: −8.33 … 8.33»). Штриховка
    заливки при любом окне остаётся под 45° на экране и с прежней плотностью — наклон и шаг
    пересчитываются в пикселях.
  • Исправлено: при увеличении окна программы график не растягивался (справа/снизу оставалось
    белое поле) — обработчик изменения размера холста перекрывал обработчик matplotlib. Теперь
    фигура всегда следует за размером холста, а после изменения размера график перестраивается.
  • Границы осей совпадают с границами холста (полей нет); подписи «x» и «y» перенесены внутрь
    области построения — к концам стрелок.
  • Исправлено: линии сетки пропадали дальше ~12 единиц от начала координат (генератор линий
    перебирал индексы вокруг нуля в пределах ширины окна). Теперь линии и деления считаются от
    границ окна — сетка есть на любом расстоянии (проверено на x ≈ 10 000 000), без ограничения
    «дальности»; защита только от слишком мелкого шага.
  • Исправлен баг: после первого перетаскивания подписи точки повторный захват не работал.
    Причина — «замок» захвата хранил id() объекта события, а Python переиспользует адреса
    освобождённых объектов: следующий клик получал тот же id и считался уже занятым. Теперь
    хранится сам объект события.

7. ВЕРСИЯ 3.0 И ИВРИТСКАЯ ВЕРСИЯ (app_he.py)
  • Текущее состояние программы объявлено версией 3.0. Ивритская версия — не отдельная копия,
    а тот же app.py с языком интерфейса LANG = "he": app_he.py запускает его с ивритом, поэтому
    обе версии всегда совпадают по возможностям. Сборка: build_he.bat → dist\FuncVisualizer_he.exe
    (generate_spec_he.py использует общий генератор спека с точкой входа app_he.py).
  • Раскладка зеркальная: панель настроек справа, график слева; оси графика по-прежнему направлены
    вправо и вверх, формулы в редакторе — слева направо (математика).
  • Шрифты: ивритский текст — David (если нет — David CLM / Frank Ruehl CLM / Noto Serif Hebrew),
    цифры, латиница (e, π, ln, sin…) и формулы — прежний шрифт программы. Смешанные подписи
    («חיתוך עם X», «צעד X:») собираются из фрагментов с разными шрифтами и раскладываются справа
    налево; на Windows ивритские фрагменты зеркалит сама система (как в старой ивритской версии).
  • Переведено всё: карточки, кнопки, подписи полей, галочки, подсказки клавиатуры, строка состояния
    (включая «נראה x: …»), сообщения об ошибках формул (редактор и движок), диалоги сохранения/
    открытия, меню и диалоги свободных подписей на графике. Ивритский текст в свободных подписях
    на графике отображается в правильном порядке (простой bidi для matplotlib) шрифтом David.
  • Файлы проектов (.fvproj) совместимы между версиями: стили линий/заливок хранятся по-английски.
  • Исправлен генератор спека: после переноса шаблона внутрь write_spec() строки спека получали
    лишний отступ, и PyInstaller падал с IndentationError. Добавлен тест tests\test_build_spec.py,
    который генерирует оба спека и компилирует их. Обе сборки (exe и exe_he) проверены.
  • Знаки препинания в ивритских подписях (по скриншотам с Windows). Раньше фрагменты без
    иврита («X:», «f1 / f2 —», «…») рисовались слева направо, поэтому двоеточие и тире
    оказывались справа от слова, многоточие — справа от текста, а пробелы между фрагментами
    пропадали. Теперь визуальный порядок символов считается по правилам Unicode Bidi
    (function_visualizer.bidi_visual: нейтральные знаки берут направление окружения или абзаца,
    числа и латиница не переворачиваются, скобки зеркалятся): «:X צעד», «עד / מ :X», «…שמור תמונה»,
    «— f1 / f2», «X חיתוך עם», «:f1». Это работает для всех подписей, чекбоксов, подсказок,
    строки состояния, кнопок, заголовка окна, диалогов, меню подписей на графике, списков стилей
    и сообщений об ошибках формулы. Учтено, что Tk на Windows (GDI) сам переставляет ивритские
    буквы, считая абзац направленным слева направо: ему отдаётся строка, которую он нарисует
    в нужном виде; на Linux/macOS и в matplotlib отдаётся готовый визуальный порядок.
    Многострочная подсказка карточки «תוויות על הגרף» переносится по строкам и раскладывается
    построчно. Тесты: tests\test_bidi.py (в т.ч. проверка модели Windows на всех переводах).
  • Строка состояния больше не выдавливается за нижний край окна (обе версии): бэкенд matplotlib
    при показе холста запрашивал для него размер фигуры (7×7 дюймов ≈ 700+ px), и в невысоком
    окне pack не оставлял места под строку состояния. Запрашиваемый размер холста теперь
    маленький, реальный задаёт растяжение окна.
